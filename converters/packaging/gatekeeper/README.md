# Rego → Gatekeeper ConstraintTemplates

**Status:** shipping (generator, round-trip test, Artifact Hub metadata); needs Gatekeeper >= 3.17 (Rego v1)
**Kind:** packaging — the policy source rides inside the template under `libs`, with its package rewritten to `lib.*`
**Covers:** the admission-shaped policy sets — `k8s_pss.main` (Pod Security Standards, baseline/restricted by parameter)
and `kubernetes.admission` (the AAC admission gate). CIS/STIG/NSA Kubernetes sets evaluate cluster facts, not
objects, and are not Gatekeeper material.

```
python3 converters/packaging/gatekeeper/build.py     # -> out/templates/*.yaml, out/constraints/*.yaml, dist/
kubectl apply -f converters/packaging/gatekeeper/dist/k8spssprofile/template.yaml
kubectl apply -f converters/packaging/gatekeeper/dist/k8spssprofile/samples/constraint.yaml
```

`dist/` is committed (regenerated by CI, `git diff --exit-code` guards it) so Artifact Hub can index it: each
package directory carries `artifacthub-pkg.yml`, `template.yaml` and `samples/constraint.yaml`. Register the
repository on artifacthub.io as kind "Gatekeeper policies" with path `converters/packaging/gatekeeper/dist`.

`test/roundtrip.sh` evaluates the generated adapter + rewritten libs with plain OPA on a Gatekeeper-shaped input
and compares the violation messages with the original policy on the same object (CONTRACT rule 5). `gator test`
is the in-cluster equivalent.
