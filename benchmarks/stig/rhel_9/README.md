# DISA STIG Red Hat Enterprise Linux 9 (V2R10)

**Coverage label: partial** (see [`scripts/coverage_labels.json`](../../../scripts/coverage_labels.json) and the
label table in [COVERAGE.md](../../../COVERAGE.md)).

## What is in the module

- All 445 rules of the V2R10 STIG. Each rule's condition is written against DISA's full check text: 104 were
  reviewed on 2026-11-18 (CHANGELOG, "DISA STIG RHEL 9 V2R10: rules test what the check text tests", #320) and
  the other 341 were added on 2026-11-22 (CHANGELOG, "DISA STIG RHEL 9 V2R10: all 445 rules").
- 366 rules are decided from collected facts alone, 77 from facts plus an attestation the check text asks for
  ("ask the SA", "documented with the ISSO"), and 2 are attestation only (RHEL-09-211015, RHEL-09-653030).
- Generated by `tools/stig_generators/gen_rhel9.py` from the reviewed rule tables
  `tools/stig_generators/rhel9_rules.py` and `rhel9_rules_part1.py` to `rhel9_rules_part5.py`; edit the tables
  and regenerate, not the `.rego` files.
- Pass, fail and evidence-missing tests per rule under `tests/`.
- The facts a collector must supply (484 paths and 98 attestation keys) are listed, with types and examples, in
  [`../LINUX_COLLECTOR_CONTRACT.md`](../LINUX_COLLECTOR_CONTRACT.md).

## Why "partial", not "validated"

The 104 rules reviewed first ran against facts from a real RHEL 9.6 host on 2026-11-20. The 341 rules added on
2026-11-22 are unit-tested but have not run against a real host, and no collector supplies most of their fact
paths yet, so on a real host they report `evidence missing` instead of a pass or a fail. The result is
fail-closed and trustworthy as far as it goes, but it is not a full assessment until a collector supplies the
paths in the contract. Where DISA's check text can be read more than one way, the reading taken is recorded in
the comment on the rule's table entry.
