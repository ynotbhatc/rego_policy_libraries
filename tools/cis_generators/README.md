# CIS module generators

Generators that build a CIS benchmark module from a workbook or text extraction the
operator supplies locally. Those files are CIS-licensed and are not committed.
Each script checks recommendation ids (and, where noted, a keyword of the
workbook title) against its hand-authored logic table, then emits the module
and its tests.

Emitted wording is original. `neutralize.py` rewrites a workbook title into a
short description of the check before anything is written. The benchmark
sentence is not copied into the module, the tests, or the committed keyword
digest. See CONTRIBUTING.md, "No verbatim CIS benchmark text."

- `gen_oracle_db_23ai.py <23ai.txt>` — CIS Oracle Database 23ai Benchmark v1.0.0,
  all 87 recommendations. Logic is written from each recommendation's audit SQL:
  parameter and profile checks read the queried value, privilege checks read the
  rows the query returns, audit checks read the enabled unified-audit options; the
  nine Manual recommendations are attestation booleans. The input contract is the
  Oracle Database 19c STIG module's, so one collector feeds both. Deprecated:
  CIS renamed the benchmark to 26ai (below).

- `gen_oracle_db_26ai.py <workbook.xlsx>` — CIS Oracle Database 26ai Benchmark v1.0.0,
  all 94 recommendations (81 Automated, 13 Manual), from the CIS workbook (needs
  openpyxl). Ids, Automated/Manual status and the three Level 1 profiles
  (RDBMS; RDBMS on Linux / Windows host) are read from the workbook; the logic table
  carries over the 23ai logic plus the seven new recommendations. Automated checks
  fail closed with an "evidence missing" message per recommendation, and the
  generated tests give every recommendation a pass, a fail and (Automated) an
  evidence-missing case. Same input contract as 23ai.

- `gen_windows_server_2022.py <workbook.xlsx>` — CIS Microsoft Windows Server 2022 Benchmark v5.1.0, all
  408 recommendations, from the benchmark's Excel workbook (Combined Profiles sheet, read with the standard
  library). Registry checks are derived from each audit procedure, with the operator taken from the title;
  account policy, user rights and the Manual recommendations come from hand-written tables in the script.
  The evaluator and its unit tests are templates beside it (`windows_lib.rego.tmpl`,
  `windows_lib_test.rego.tmpl`); the per-recommendation tests are generated by
  `gen_windows_server_2022_tests.py`. Run `python3 scripts/coverage_stamp.py` afterwards.

- `gen_windows_server_2016.py <workbook.xlsx>`: CIS Microsoft Windows Server 2016 Benchmark v4.0.0,
  422 recommendations (420 Automated, 2 Manual; 415 in the L1/L2 x DC/MS profiles plus 7 opt-in Next
  Generation). The 2019 generator pointed at the 2016 workbook: same reader, derivation, evaluator template,
  report contract and test builder. Holds only what differs: the folding of a sheet that lists each
  recommendation once per profile with a tier prefix on the title, the 2016 tables (account policy, the older
  2.3.1.x numbering, the time-zone right, registry overrides restated per id with a title keyword), a minimum
  inside a several-value row (18.10.93.4.2) and a conditionally allowed principal (2.2.33). Writes
  `benchmarks/cis/windows_server_2016_modular/` including its README, and formats it with `opa fmt` when
  `opa` is on the path.

  The Windows generators (2022, 2019, 2016, 10, 11) remove and overwrite only their own output, recognised by
  the "Generated by" / "Copied into" / "Written into ... tools/cis_generators/<script>" comment that opens
  every file they write (`remove_generated` and `write_generated` in `gen_windows_server_2022.py`).
  Hand-written files in a module directory, such as the framework-key bridges `cis_windows_2019_key_main.rego`
  and `cis_windows_2022_key_main.rego`, are left in place, and a generator aborts rather than overwrite one.
