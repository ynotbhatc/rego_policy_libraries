Coverage Labels: Validated, Partial, Experimental

Every framework key carries one coverage label, so the library cannot claim more than it has shown. A passing unit test proves a rule does what its author meant; it does not prove the rule reads what a real collector sends. Validated means the framework has been run against real host or tenant evidence and the results checked. Partial means the rules are implemented and tested but the evidence or collector is incomplete, or only part of the benchmark is covered. Experimental means generated or new and not yet run on real evidence: treat its results as unverified. The labels are kept in scripts/coverage_labels.json, and CI fails when a framework key has no label.

  • validated Run against real host or tenant evidence and the results checked; the evidence says where.
  • partial Rules implemented and unit-tested, but the evidence or collector is incomplete, or the module covers a subset of the benchmark; the evidence says what is missing.
  • experimental Generated or new; unit-tested at most, not yet run on real evidence. Treat its results as unverified.
